================================================================
6. STAGE 1 ARCHITECTURE
================================================================

Perception:
- USB monocular camera
- lightweight person detector
- tracker after detector to reduce box flicker and target switching
- output is selected target 2D box

Fusion:
- use camera intrinsics
- use camera-to-MID360 extrinsics
- project lidar points into image plane
- select points inside target box
- reject outliers
- estimate target 3D position relative to aircraft

Control:
- do NOT start with EGO
- do NOT start with full trajectory planner
- compute simple low-speed follow commands from target relative pose
- command set should be:
  - forward or backward correction
  - lateral correction
  - yaw rate correction
- send result into PX4 Offboard through a dedicated adapter layer

State machine:
- idle
- target_acquired
- follow
- search
- lost

Key principle:
- Replace Stanley's DroneKit downstream with a PX4-friendly downstream.

================================================================
8. THREE MAIN RISKS
================================================================

RISK 1: camera-to-MID360 extrinsic calibration
- This is the biggest technical risk.
- If the extrinsic is wrong, target distance and lateral position will drift.
- Follow behavior will oscillate or fly biased.

RISK 2: sparse or unstable target point association
- Human points inside the box may be sparse or noisy.
- Need temporal filtering and outlier rejection.
- Need fallback behavior when depth estimate is weak.

RISK 3: overcomplicated early control
- First version must not jump into full trajectory planning.
- First version must solve smooth low-speed follow only.
- Otherwise debugging surface becomes: detector + tracker + fusion + planner + bridge + offboard.

12. INITIAL CONTROL LAW SHAPE
================================================================

Stage1 control should prefer low-speed body-frame control.

Inputs:
- target x in body frame
- target y in body frame
- target z or forward distance in body frame

Outputs:
- vx_body
- vy_body
- yaw_rate

Constraints:
- low speed only
- saturations mandatory
- deadbands mandatory
- hold behavior when confidence is weak
- search behavior when target is lost

Do NOT start with aggressive position jumps.
